# A1 予約管理の統合範囲と他スレッドとの接続

更新：2026-11-03。PR #33と#55を最新mainに統合する作業用ブランチの仕様です。本番稼働の確認記録ではありません。

## 範囲

- A1：申込一覧、○△□×、貸出条件の記録、案内送信、重複判定、管理者による最終承認。
- A2：料金計算の仕様、追加料金、検証済み請求額、収支。A1は既存mainの料金計算を変更しません。
- A3：貸出返却、免許証、写真、帳票。今回追加しません。
- A4：銀行接続、入金照合、カード・QR・返金。今回銀行APIを呼ぶコードは追加しません。
- B：SNS、LINE通知、集客。今回追加しません。

## データの所在と現行の識別子

| 対象 | 現行コードでの所在 | 注意点 |
|---|---|---|
| 申込内容 | フォーム回答タブ | 読取専用。列の実構成は要確認 |
| applicationId | 申込タイムスタンプISO文字列のSHA-256 | #33の識別子を維持。全業務の共通IDとしては未確定 |
| fingerprint | 回答行全体のSHA-256 | 回答編集時は変わり、既存の金額・条件確認を失効させる |
| 案内金額・送信結果 | SUN_AID_送信履歴のenvelope・status | フォーム概算額とは区別する |
| 貸出区分・条件・確認済み請求額・商談終了 | SUN_AID_予約対応のdata(JSON) | applicationIdとfingerprintに関連付ける |
| 確定履歴・確定日時 | SUN_AID_予約確定履歴 | 管理者の最終承認で記録する |
| 予約済み時間・△期間 | 設定されたGoogleカレンダー | 他のカレンダーやCarstayを自動取得する機能はない |
| 入金照合結果 | 未接続 | 現段階は最終承認時の管理者による確認 |

予約IDを別形式へ変更する場合は、00統括とA2で移行方法を決めます。この統合で別の顧客・収支台帳を新設しません。

## 状態と商談の扱い

申込受付で□。銀行入金があっても、管理者の最終承認までは□です。承認操作で同一Script Lock内の再検査・カレンダー登録・確定履歴記録を行い、以後は×になります。

□はカレンダーイベントでなく有効な未確定申込から算出します。後続からの問い合わせは受け付けますが、重なる先行商談がある限り、後続の振込案内・確定を停止します。重複したタイムスタンプは識別不能として両案件を停止します。

商談期限・自動失効の時間は未決定です。今回は管理者による商談終了を用意し、経過時間を理由に自動解除しません。既存の確定予約の取消・日時変更は今回の商談終了操作の対象外です。

## 自動案内の実装状態

実装済み：両フラグ有効時に、確認済み金額・貸出区分・条件了承・最新空き状況・先行商談を検査して案内を送るエンジン。送信済み・結果不明・失敗・準備済み案件は自動再送しません。自動で予約確定はしません。

未接続：新規申込みを通常案件と自動判定する規則、フォーム入力とは独立した自動の請求額検証、定型条件の自動提示と顧客了承の自動取得。現在の確認済み金額は管理者の保存操作を出所とします。

貸出条件と金額の確認保存は `saveReview`。必要項目はapplicationId、fingerprint、eligibility（standard/conditional）、approvedAmount、amountVerified=trueです。conditionalでは条件文が必須で、案内前にconditionsAccepted=trueが必要です。これは認証済み管理者向け操作であり、A2の自動接続APIとして確定したものではありません。

## A2・A4と合意が必要な接続項目

| 相手 | 受け渡す必要がある情報 | 今回の実装 |
|---|---|---|
| A2 | 申込ID・改訂識別、利用日時、検証済み請求額、金額の対象範囲と根拠 | 既存IDと管理者確認額を維持。自動価格検証の接続は未実装 |
| A4 | 対応する申込/請求ID、照合状態、入金額、銀行取引識別子、確認時刻 | 未接続。A1では銀行照合機能を作らない |

車両概算額・請求額・予定返金額・実入金額を一つのamountにまとめません。A2の仕様確定前に、フォームの概算額を自動請求額とみなしません。

## 統合と検証

- 最新mainを基点に#55を取り込むため、#55の親である#33も含まれます。元PRのブランチには変更を加えません。
- mainの最低料金・祝日判定・料金表示の更新を維持します。「概算料金」「車両の概算料金」の両入力形式に対応し、二重記載は拒否します。
- Node 22で予約管理35件・料金計算27件を実行し、62件成功。
- 架空データによるブラウザ確認：一覧、条件・金額保存、条件未了承時の停止、重複確認結果、承認前の金額変更による停止、最終承認後の表示、○△□×、□日の時刻選択。
- 実フォーム、稼働GAS、カレンダー権限、実メール、Vercel PreviewのGoogle接続は未検証です。

## 接続先の確認で残っていること

現在利用できるDrive検索では予約用の回答シートを特定できず、利用できるカレンダー一覧にもコードが想定する「予約」を特定できません。会社名のカレンダーが見えることだけを理由に設定先へ採用しません。

実際のフォーム回答スプレッドシートURLを起点に、関連するGASと稼働トリガー、予約カレンダー、Vercelの接続版を確認します。稼働中スクリプトの全置換、Googleの権限変更、自動送信の有効化は、対象を特定して検証する前には実施しません。
